# Dashboards are built on Dash Server (munich-mobility-agents)

- Any request to create, build, make, show, draw or update a **dashboard, chart, graph, plot, view, visualisation, report page, executive view or KPI page** from Exasol data MUST be built on **Dash Server**: drive the `dash-server` MCP control plane (`app_create_exasol_dashboard` → `app_put_files` → `app_deploy_draft` → `app_run_healthcheck`; on Windows `app_build` → `app_run_healthcheck` → `app_promote_revision`) following the `persona-metrics` skill, then give the user the dashboard URL from `exakit status --json` (default http://127.0.0.1:5100).
- NEVER satisfy such a request with an Artifact, an HTML or React page, `show_widget`, an inline SVG, a matplotlib/plotly image, a Markdown table called a "dashboard", or a Streamlit/Flask app. If the dash-server tools are missing, do not stop and do not fall back: install the add-on with `exakit marketplace dash-server`, register it with `exakit mcp-setup`, start it with `exakit start`, confirm with `exakit status`, then tell the user to restart Claude so the dash-server tools load, and continue from there.
- A bare "create a dashboard" with no persona or question: ask one clarifying question (which persona or which question), then build it on Dash Server.
- Munich persona questions are routed by topic, the user never has to name an agent: roadworks / disruption / construction near stops → `mobility-operations`; district coverage, population vs transport or cycle paths → `urban-planning`; cycling demand, counters, weather → `sustainability`; priorities across all of these, executive view → `city-leadership`. Load the `munich-mobility-agents` skill and delegate to that subagent in `~/.claude/agents/` with the Agent tool; relay its answer, SQL, gaps and dashboard URL.
- All SQL runs through the read-only `exasol` MCP server. Show the SQL before interpreting its result. Say plainly what the data cannot answer (MVV GTFS is scheduled service: no passengers, delays or live traffic).
